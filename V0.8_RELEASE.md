# MNCS Registry V0.8

A polished directory and administration workspace for the existing registry.

## What changed

- A new national-registry landing page, consistent design, local styles, local
  Supabase browser library, responsive directory and compact source indicators.
- Sport, registration-status and profile-verification filters; alphabetical
  sorting; 12 records per directory page; filtered CSV export with protection
  against spreadsheet formula interpretation.
- Keyboard-accessible detail actions and modal focus trapping, Escape dismissal,
  focus restoration, labelled search and filters, skip navigation and reduced
  motion support. Registry search is hidden on workspace and awards screens.
- Public association details show the source listing and profile verification.
  An approved profile is not presented as a certified MNCS affiliation decision.
- Readable submission fields replace the default raw JSON display. Change history
  remains available in a collapsed audit section.
- A read-only account-service status panel identifies missing server settings
  without returning credentials. Reviewer accounts no longer require selection
  of an association. Generated passwords clear after successful account creation.
- Live mode loads registry rows only. Empty athlete, event or result collections
  stay empty. It never fills missing live collections with sample records.
- Connection failures show a retry panel without replacing or deleting the
  workspace DOM. Existing loaded records remain visible until refreshed.

## Deploy

1. Export/backup your project data.
2. Run supabase/INSTALL_ALL.sql in your existing Supabase project. It contains all
   implemented migrations and sourced association candidates. Existing records
   and initial administrator setup state are preserved.
3. In Netlify, enable these variables for Functions in the production context:
   - SUPABASE_URL = https://owvuayretqnibwwhonch.supabase.co
   - SUPABASE_SECRET_KEY = your PRIVATE Supabase secret/service-role key
   - SITE_ORIGIN = https://mncsdb.netlify.app
4. Upload all project files to the Git repository linked to Netlify and redeploy.
   Keep index.html at the root and netlify/functions intact. A static-only drag
   and drop deployment does not provision the account service.
5. Workspace > Create accounts now checks server setting presence. Presence is
   not validation of the private key; create a real reviewer and association
   account to verify provisioning. Do not put the private key in GitHub or chat.
6. Confirm the dashboard counts match live registry rows. The expected absence
   of published athlete or result rows should display zero counts and empty lists.

MNCS_SETUP_CODE is needed only for first-administrator setup. Existing admins
should sign in; they should not bootstrap another initial account.

## Demonstration and sources

Open demo.html for the isolated in-memory simulator. Its three role buttons
avoid typing; pseudo accounts use 1234. It makes no Supabase or account-service
requests. Changes and attached demo PDFs reset on reload. Do not enter real
credentials or personal records there.

The 29 researched candidates retain their provenance from the Malawi Olympic
Committee directory. This does not establish their current MNCS affiliation.
Editing association basics preserves stable IDs, source metadata and documents.

## Tests and present limits

See V0.8_TEST_REPORT.md for the performed checks. Live browsing, local DOM
interaction tests and unit tests are reported separately. No live accounts,
production SQL or Netlify settings were changed by the developer during this
release. Actual live provisioning and RLS isolation remain deployment checks.

Awards still support cycle configuration and eligibility dossiers. Official
judge scoring, live ballots/fan polls, audited results and appeals are not
operational. The existing transparent policy and strict under-20 rule remain.
This release does not add athlete, event or result entry forms. Those collections
can display published records, but a complete reviewed record-entry workflow is
still required. Password recovery emails and required first-login rotation also
remain future work. This is a stronger registry foundation, not a certification
of production readiness.

## Rebuilding optional assets

The compiled CSS and Supabase library are shipped; no build is required to serve
this package. To edit styles, run Tailwind 3.4.17 from the repository root with:

    npx --yes tailwindcss@3.4.17 -c scripts/tailwind.config.cjs -i scripts/tailwind-input.css -o css/tailwind.css --minify

Then run python scripts/build-demo.py to keep the demo shell in sync. The bundled
Supabase browser library is version 2.57.4. MIT licences are in assets/licenses.

## Netlify deployment fix: public Supabase URL

If Netlify reports `Secret env var "SUPABASE_URL"'s value detected`, the
public project URL has been classified as a secret. It is intentionally present
in the browser configuration; it is not a password or private API key.

1. In Netlify, open your project → **Project configuration → Environment variables**.
2. Add `SECRETS_SCAN_OMIT_KEYS` with the exact value `SUPABASE_URL`. Make it
   available to Builds in the production context (and other contexts you deploy).
   Leave **Contains secret values** unchecked for this new setting.
   If this variable already exists, preserve its other reviewed exclusions and
   append `SUPABASE_URL` as a comma-separated entry.
3. Keep `SUPABASE_SECRET_KEY` marked as secret. Keep `MNCS_SETUP_CODE` secret if
   it is still needed for initial setup. Do not exclude either from scanning.
4. Save and trigger a fresh production deploy from the Deploys page.
5. Check the deploy log, open Workspace, sign in, and test account creation.
   A successful build does not itself prove the account service is configured.

Do not disable secrets scanning or exclude entire files. This setting excludes
only the public project URL. Netlify does not allow removal of an existing
secret flag; the narrow exclusion avoids deleting/recreating that setting.
For new configurations, `SUPABASE_URL` and `SITE_ORIGIN` are public settings;
only the private key and temporary setup code should be marked as secret.

No SQL, database, account or password changes are needed for this deployment fix.
The application code is unchanged from V0.8. This package only clarifies setup.

Reference: https://docs.netlify.com/build/environment-variables/secrets-controller/
