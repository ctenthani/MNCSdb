# MNCS Registry v0.7

## Install and correct the account creation error

The screenshot showed `Request origin is not authorised`. This is a server
origin configuration failure, before any attempt to create a Supabase user.

1. In Netlify, set SITE_ORIGIN to https://mncsdb.netlify.app. Enable the variable
   for Functions in the production deploy context. Do not include quotes.
2. Retain SUPABASE_URL and your private SUPABASE_SECRET_KEY in Functions.
   This is the private secret/service-role key, not the frontend publishable key.
3. Run supabase/INSTALL_ALL.sql. It includes all migrations and researched
   association candidates. Existing data and administrator setup are preserved.
4. Deploy this complete project through the Git repository linked to Netlify.
   Redeploy after changing environment variables.
5. Sign in and test Create accounts for a reviewer and an association account.

Origin matching now normalises surrounding whitespace and trailing slashes,
handles header casing, and accepts Netlify's trusted primary URL when available.
It still rejects arbitrary origins, missing origins and wildcard hosts. Secret
keys beginning sb_secret_ are sent in apikey, not as JWT bearer tokens.

## Passwords and account management

Real accounts retain the 12-character application minimum. Use Generate and
fill password to avoid typing passwords twice. It fills a unique 20-character
password and shows it for copying; no password is stored in the profiles table.
Supabase may enforce additional project-level requirements.

Workspace > Security now lets an MNCS administrator reset the password of any
managed MNCS or association user, one account at a time. Reviewers and
association representatives cannot reset other users. Share reset passwords
privately. This does not revoke every existing token instantly and does not
implement mandatory password changes at the next login.

| MNCS reviewer | reviewer@mncs.example | 1234 |

These are fictional, in-memory accounts. They do not authenticate to Supabase,
call the account function, or change your real passwords. This simulator resets
on reload. PDF evidence remains available in the current page session only.
New pseudo accounts and password resets work inside the demo. Do not enter real
personal data or credentials into it. The source list is public reference data.

## Researched associations and editing

29 candidate associations come from the Malawi Olympic Committee directory:
https://www.moc.org.mw/associations/ (researched 2 October 2026).

This source establishes that MOC lists the organisations; it does not certify
current MNCS affiliation. Records include source URLs, research dates and a
verification warning. Display abbreviations are sport labels for editing, not
claims of official acronyms. The directory's wrestling spelling was corrected.
Malawi Defence Force and Malawi Police Service were excluded from the candidate
import because their listing does not establish a standalone national governing
association. This is not a complete list of MNCS affiliates.

The installer skips existing matching names or sport labels, and never overwrites
existing records. Review the candidates under Workspace > Associations. Edit
changes name, abbreviation and sport; the stable association ID, private
submissions and source metadata are preserved. Existing roles cannot be changed
by editing association basics. Imported organisations receive no Auth accounts.

## Awards responsibility and limits

The MNCS administrator should authorise opening and closing participation after
eligibility screening and shortlist confirmation. Reviewers screen dossiers;
associations nominate. Currently the app supports cycle configuration and dossier
review only. It has no operational official ballot, live adjudicator scoring,
auditor approval, publication workflow or appeals system.

Before a judges-only official result and a separate fan poll are used, MNCS must
approve and publicly disclose the handbook amendment. Fan votes must not be
presented as influencing official results if they have no effect.
