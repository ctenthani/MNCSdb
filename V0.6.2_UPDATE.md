# MNCS Registry v0.6.2

Association registration now uses the signed-in MNCS administrator session,
with an administrator-only Supabase insert policy. It no longer depends on the
Netlify account function. The policy accepts initial public association fields
only and keeps new records marked Under Review. Duplicate IDs and missing
permissions show distinct messages beside the form; failed forms retain entries.

The signed-in workspace has a welcome panel, four status cards, section
navigation, focused forms, an association directory and an account directory.
Sections depend on the user's role. The layout includes responsive styles and
visible keyboard focus indicators. The selected section survives refreshes.

## Install this update

1. Run supabase/INSTALL_ALL.sql in your existing Supabase project. Existing
   records and initial administrator setup state are preserved. Alternatively,
   owners who already installed v0.6 may run v0.6.2-migration.sql once only.
2. Deploy all project files from this package. Keep your existing Netlify server
   environment settings. Git deployment builds the account creation function.
3. Sign out and sign in again. Open Workspace > Associations and register an
   association with a unique ID. Open Create accounts for its representatives.

Local tests cover association writes, invalid details, duplicate IDs, denied
permissions, section navigation and the existing workflows. The SQL installer
has not been executed against your live database. Actual administrator,
reviewer and association permissions require live verification after deployment.
